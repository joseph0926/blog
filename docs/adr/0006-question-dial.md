# 시각 방향은 "질문 다이얼"로 바꾸고 한 가지 회전 문법을 모든 페이지가 공유한다

[ADR 0004](0004-visual-direction-lab-ledger.md)의 "연구 노트, 여백 색인"과 [ADR 0005](0005-about-scroll-scrubbed-motion.md)의 about 전용 모션 예산을 이 결정으로 대체한다. 2026-10-03에 A부터 E까지 다섯 시안을 실제 화면에서 비교했고, 정적인 목록과 문서형 구성(A, B, C)은 "index처럼 정적이다", "일반적인 HTML 데모 같다"는 판정으로 기각했다. 채택한 D는 글 제목 대부분이 질문이라는 점에서 출발해, 질문을 하나의 세로 릴로 이어 붙이고 스크롤이 그 릴을 한 덩어리로 돌리게 했다.

회전 문법은 하나다. 릴의 가운데 항목은 크고 굵고 진하며, 가운데에서 멀어질수록 작아지고 옅어지고 가늘어진다. 굵기는 Hahmlet의 가변 wght 축으로 스크럽한다. 항목은 실제 높이를 축소 비율만큼 쌓아 배치하므로 줄 수가 달라도 겹치지 않는다. 이 문법을 홈의 질문 다이얼, 글 상세의 절 다이얼, about의 장 다이얼과 작업 기록 릴이 같은 함수로 공유한다. 화면에 고정되는 릴(홈 질문 다이얼, about 작업 기록)의 트랙 높이는 `(항목 수 - 1) × 50svh + 100svh`이고, 무대 높이의 절반을 스크롤할 때마다 한 칸 넘어간다. 위키의 pinned 시퀀스 기본값(항목당 한 화면)보다 짧게 잡은 것은 질문을 훑는 속도를 위해서다. 글 상세의 절 다이얼은 읽는 동안 멈춰 있다가 다음 헤딩이 읽는 선의 200px 안으로 다가올 때만 넘어간다. 휴대폰에서는 다이얼 대신 헤더 밑에서 미끄러져 나오는 띠가 현재 절을 보여 주며, 띠는 제목이 헤더 뒤로 지나간 뒤에만 나타난다. 홈 질문을 열면 그 제목이 View Transition API로 글 제목까지 이어진다. snapshot은 비율이 다르면 늘어나므로 다이얼 항목과 글 제목은 같은 글자 크기, 줄 간격과 최대 폭(11.5em)을 써서 같은 비율로 위치만 옮긴다. API가 없는 브라우저와 저감 모드에서는 바로 이동한다.

토큰은 `packages/ui/styles/globals.css`가 소유한다. 바탕은 흰색과 검정에 가까운 무채색 단계이고 웜 hue를 쓰지 않는다. 강조색은 파랑 하나(`--accent-ink`)이며 의미는 "지금 위치와 행동"으로 제한한다. 구획은 여백, 글자 굵기, 표면 톤 순서로 만들고, border는 표의 행과 입력 필드에만 1px로 남긴다. 모서리는 컨테이너 0~6px, 버튼과 입력 4~6px이다. 서체는 제목과 다이얼에 Hahmlet, 본문에 IBM Plex Sans KR(17px, 줄 간격 1.75), 코드에만 IBM Plex Mono를 쓴다. 본문 후보로 Wanted Sans도 비교했지만 한글 분할 파일 92개를 저장소에 둬야 해서 기존 본문 서체를 유지했다.

모션 예산은 스크롤 진행값에 1:1로 묶여 사용자가 되감을 수 있는 회전, 화면 사이의 제목 morph, 150ms 안팎의 짧은 내용 교체까지다. 시간 기반 진입 fade-up, stagger, 콘텐츠의 opacity 0 시작, 장식 루프는 넣지 않는다. JS 실행 전과 `prefers-reduced-motion`에서는 모든 릴이 같은 내용을 정적 목록으로 렌더하고, 위치와 상태 정보(현재 항목의 강조)만 남긴다. about은 더 이상 lenis로 스크롤을 보간하지 않는다. 블로그 목록 페이지는 검색과 필터가 핵심 작업이므로 다이얼로 바꾸지 않고 토큰과 타이포만 따른다. `apps/blog/src/mdx/components/**`는 ADR 0002에 따라 코드를 바꾸지 않으며 토큰 값만 물려받는다.

자동 검사가 닫는 것은 정적 검사, 두 locale에서 저감 모드로 헤딩과 핵심 내용이 텍스트로 존재하는지, 좁은 화면에서 가로 넘침이 없는지까지다. 회전의 감촉, pacing, morph 속도와 미감은 사람이 실제 화면에서 판정한다. 방향을 바꾸는 결정은 새 ADR로 이 문서를 대체한다.
